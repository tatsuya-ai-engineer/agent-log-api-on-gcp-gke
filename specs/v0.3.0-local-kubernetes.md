# v0.3.0 Local Kubernetes

## 目的

Docker化済みの `agent-log-api` をローカルKubernetesで起動する。

このMilestoneでは、Kubernetesでアプリを起動し、ローカルPCからアクセスするまでの流れを学ぶ。

**Pod**：Kubernetesがコンテナを動かす最小単位である。

**Deployment**：Podが常に指定した数だけ動くように管理する設定である。

**Service**：Podが作り直されても変わらない接続先を用意する設定である。

**port-forward**：ローカルPCのポートとServiceのポートを一時的につなぐコマンドである。

このSpecでは、`kubectl port-forward` によりローカルPCのポート8000からAPIへ接続する。

## 前提

Docker DesktopでKubernetesを有効にする。

`kubectl config current-context` がDocker Desktopのローカルクラスタを返し、`kubectl cluster-info` が成功する状態にする。

Dockerイメージ `agent-log-api:local` を、リポジトリのルートで次のコマンドにより作成しておく。

```sh
docker build -t agent-log-api:local services/agent-log-api
```

ホストのポート8000が使用中の場合は、そのプロセスを停止するか、port-forwardのローカル側に別のポートを指定する。

## 範囲

| 対象 | 内容 |
|---|---|
| manifest配置先 | `k8s/agent-log-api/` にDeploymentとServiceのmanifestを置く。 |
| Deployment | `apps/v1`のDeploymentで`agent-log-api` Podを1つ起動する。 |
| コンテナ | イメージは`agent-log-api:local`、コンテナポートは8000、`imagePullPolicy`は`IfNotPresent`とする。 |
| Service | `ClusterIP`のServiceで、port 8000をDeploymentのcontainerPort 8000へ転送する。 |
| ラベル | Deploymentのselector、Pod template、Serviceのselectorで同じ`app: agent-log-api`ラベルを使う。 |
| 接続 | `kubectl port-forward service/agent-log-api 8000:8000` でローカルのポート8000から接続する。 |
| 確認 | `GET /health` がHTTP 200と`{"status":"ok"}`を返すことを確認する。 |
| 手順 | READMEに、Kubernetes有効化後のbuild、適用、確認、削除の順で記載する。 |

## 実装後の実行手順

この節のコマンドは、DeploymentとServiceのmanifestを実装した後に実行する。

すべて、リポジトリのルートで実行する。

### 1. Docker DesktopでKubernetesを有効にする

Docker Desktopを開く。

SettingsのKubernetesを開き、Kubernetesを有効にして適用する。

Docker Desktopが再起動し、Kubernetesの起動が完了するまで待つ。

ターミナルで次のコマンドを実行する。

```sh
kubectl config current-context
kubectl cluster-info
```

最初のコマンドで`docker-desktop`が表示され、二つ目のコマンドでクラスタ情報が表示されれば準備完了である。

### 2. APIのDockerイメージを作る

Kubernetesが起動する元になるDockerイメージを作る。

```sh
docker build -t agent-log-api:local services/agent-log-api
```

コマンドが最後までエラーなく終了すれば、イメージの準備は完了である。

### 3. KubernetesへDeploymentとServiceを作る

次のコマンドは、`k8s/agent-log-api/` にある設定ファイルをKubernetesへ登録する。

```sh
kubectl apply -f k8s/agent-log-api/
```

`deployment.apps/agent-log-api created`などの表示が出れば、設定の登録は成功している。

### 4. Podの起動を待つ

DeploymentがPodを起動し、APIを使える状態になるまで待つ。

```sh
kubectl rollout status deployment/agent-log-api
```

`deployment "agent-log-api" successfully rolled out`と表示されれば、Podは準備完了である。

### 5. ローカルPCとServiceをつなぐ

別のターミナルを開く。

次のコマンドは、ローカルPCのポート8000へのアクセスをServiceへ転送する。

```sh
kubectl port-forward service/agent-log-api 8000:8000
```

`Forwarding from 127.0.0.1:8000`と表示されたまま、このターミナルは開いておく。

### 6. ヘルスチェックを確認する

さらに別のターミナルを開く。

次のコマンドで、Kubernetes上のAPIが応答するかを確認する。

```sh
curl -i http://localhost:8000/health
```

`HTTP/1.1 200 OK`と`{"status":"ok"}`が表示されれば成功である。

### 7. 作成したリソースを削除する

まず、port-forwardを実行しているターミナルで`Control` + `C`を押して転送を止める。

次のコマンドで、このMilestoneで作成したDeploymentとServiceを削除する。

```sh
kubectl delete -f k8s/agent-log-api/
```

`deleted`と表示されれば削除は完了である。

## 受け入れ条件

- [ ] Docker DesktopのKubernetesを有効にした環境で、`kubectl cluster-info` が成功する。
- [ ] `docker build -t agent-log-api:local services/agent-log-api` が成功する。
- [ ] `kubectl apply -f k8s/agent-log-api/` が成功する。
- [ ] `kubectl rollout status deployment/agent-log-api` が成功し、PodがReadyになる。
- [ ] Serviceのport、targetPort、DeploymentのcontainerPortがすべて8000で一致する。
- [ ] `kubectl port-forward service/agent-log-api 8000:8000` の実行中に、`GET /health` がHTTP 200と`{"status":"ok"}`を返す。
- [ ] READMEの手順だけで、build、適用、確認、削除を再現できる。
- [ ] `kubectl delete -f k8s/agent-log-api/` の後に、作成したDeploymentとServiceが残らない。
- [ ] API仕様、ログスキーマ、認証方式、保存方式を変更しない。

## 対象外

- GKE、GCP、Artifact Registry、コンテナイメージのリモート公開。
- Namespace、ConfigMap、Secret、ServiceAccount、Probe、Resource Requests/Limits、Ingress、Gateway、NetworkPolicy、HPA。
- Kubernetes上での永続化、ログの外部保存、APIの仕様変更。
- CIでのmanifest検証、Dockerイメージbuild、クラスタへのデプロイ。

## 制約

このMilestoneでは、Docker Desktopのローカルクラスタだけを対象にする。

ローカルイメージ `agent-log-api:local` を使うため、GKEなど別のクラスタへmanifestをそのまま適用してもイメージを取得できない。

`agent-log-api` はログをメモリに保存するため、Podが再作成されると受信済みログは消える。

ConfigMap、Secret、Probeは `v0.5.0 Ops Readiness` で扱う。
