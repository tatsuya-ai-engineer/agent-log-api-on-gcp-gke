# v0.2.0 Docker

## 目的

`agent-log-api` をDockerイメージとしてbuildし、ローカルのコンテナから起動できるようにする。

このMilestoneでは、Kubernetesへ進む前に、アプリケーションと依存関係を一つのコンテナ実行単位として確認する。

## 前提

Docker CLIとDockerデーモンが利用可能であることを前提とする。

ローカルではDocker Desktopを起動してから、buildとcontainer起動を実行する。

ホストのポート8000が使用中の場合は、既存プロセスを停止するか、実行時に別のホストポートを指定する。

## 範囲

| 対象 | 内容 |
|---|---|
| build context | `services/agent-log-api` をDocker build contextにする。 |
| Dockerfile | Python 3.12 slim系の公式イメージを基底にし、`requirements.txt` の依存関係をインストールしてアプリケーションを配置する。 |
| 起動コマンド | Uvicornを `--host 0.0.0.0 --port 8000` で起動する。 |
| ポート | コンテナのポート8000を公開し、ローカルではホストのポート8000へ割り当てる。 |
| 除外設定 | `.venv`、pytest cache、Python cache、Git管理情報などを`.dockerignore`でbuild contextから除外する。 |
| 手順 | READMEにbuild、起動、停止、`GET /health`の確認手順を記載する。 |

## 実行方法

リポジトリのルートから次のコマンドでイメージをbuildする。

```sh
docker build -t agent-log-api:local services/agent-log-api
```

次のコマンドでコンテナを起動する。

```sh
docker run --rm -p 8000:8000 agent-log-api:local
```

別のターミナルから次のコマンドを実行し、ヘルスチェックを確認する。

```sh
curl http://localhost:8000/health
```

## 受け入れ条件

- [ ] `docker build -t agent-log-api:local services/agent-log-api` が成功する。
- [ ] `docker run --rm -p 8000:8000 agent-log-api:local` でコンテナが起動する。
- [ ] コンテナ起動中に `GET /health` がHTTP 200と `{"status":"ok"}` を返す。
- [ ] `.dockerignore` によりローカル仮想環境、テストcache、Python cache、Git管理情報がbuild contextから除外される。
- [ ] READMEの手順だけでbuild、起動、停止、ヘルスチェックを再現できる。
- [ ] 既存のAPI仕様、ログスキーマ、認証方式、保存方式を変更しない。

## 対象外

- Kubernetes manifestの作成と変更。
- GCP、Artifact Registry、コンテナイメージのリモート公開。
- CIでのコンテナイメージbuildとpush。
- Docker Composeの追加。
- API仕様、ログスキーマ、認証、永続化の変更。
- コンテナの再起動をまたぐログ保持。

## 制約

`agent-log-api` はログをメモリに保存するため、コンテナを停止すると受信済みログは消える。

ソースコードを変更した場合は、コンテナを再起動するだけでは反映されないため、イメージを再buildする。

このMilestoneでは、Dockerコンテナをローカルで実行することだけを確認する。

Kubernetesへの配置と、コンテナイメージの配布は後続Milestoneで扱う。
